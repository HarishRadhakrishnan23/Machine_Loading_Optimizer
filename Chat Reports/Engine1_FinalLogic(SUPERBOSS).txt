2. BATCHING Logic
	I will explain the Batching Logic with more specfic Example down below, but try to understand from this explanation and correlate it with the logic.
		1. Now the Whole concept of adding SETUP_TIME before every First Piece is lost and rather we add a Concept of Fixture and Locator. See, every SIZE~CLASS~MOC~DESIGN will have Locator attached to a Fixture. See every PARTICULAR SIZE~CLASS~MOC~DESIGN will have Fixed Fixture and Locator and every similar SIZE~CLASS will have Fixture same but only the Locator change.
		2. When the Fixture is changed, both the FIXTURE_CHANGE_TIME (Time taken to change the Fixture) and LOCATOR_CHANGE_TIME (Time taken to change the Locator) from the MCH_ITEMWISE_FIXTURE_LOCATOR table, is added before the first piece of that batch.
		3. When only the Locator is changed, the LOCATOR_CHANGE_TIME from the MCH_ITEMWISE_FIXTURE_LOCATOR table, is added.
		4. Apart from this LOAD_UNLOAD_TIME is added for every piece in that batch so LOAD_UNLOAD_TIME should be multiplied with total quantity of that Batch which Engine1 has grouped.
		5. Whenever we change the MOC (both when inbetween two batches or within the batch), at the first piece we add CLEANING_TIME. Its a small time taken to clean between MOC changes.
		6. Same SIZE~CLASS~MOC~DESIGN and Same operation should not be ideally carried out in different machine at same time or instance ., For Example if an 10~150~Carbon Steel~DF order is planned for Op10 today., I want the algorithm to combine all the orders of same 10~150~Carbon Steel~DF on operation 10 with same Fixture and Locator (or) same Fixture but different Locator to be grouped together on the same day at maximum cases.
		7. A fixed SIZE~CLASS~DESIGN will have fixed FIXTURE and LOCATOR in MCH_ITEMWISE_FIXTURE_LOCATOR., in cases where orders of batch may consist of both Priority orders (CDD is not null) and Safety Stock order (where CDD is null) and when these batches go through higher time consuming Task like VB03 (Weld overlay), Stemboring, Cone Finish and StemBore + Cone Finish (VB04, VB05, VB06), It is usually better to go with batch without Safety stock. In those case u might consider safety stock as last priority., but I still need your help on how to handle this situation. 
		   7.1. But An important thing is in MCH_FIXTURE_LOCATOR table you will give you information on how many fixture (DEVICE_NAME = (Fixture ID) and DEVICE_TYPE = "F") are available on that particular Fixture ID in our shop floor material stock and simililarly No of Locators (DEVICE_NAME = (Locator ID) and DEVICE_TYPE = "L") of that particular Locator ID in our shop floor material stock. We HAVE TO add two new columns in MCH_SCHEDULE_OUTPUT (Engine1 result) in such a way that every time we assign a production order of an operation to a Machine we have to record the Fixture ID and Locator ID from DEVICE_NAME of MCH_FIXTURE_LOCATOR and record it in the two new columns created in MCH_SCHEDULE_OUTPUT, this is done because there are only a fixed no of Fixtures and Locators., and the batching should take that into consideration.
