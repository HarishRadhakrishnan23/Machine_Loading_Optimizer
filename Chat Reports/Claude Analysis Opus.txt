  C1 — urgency_weight formula is incomplete.
  CLAUDE.md defines three components — pdd_score, ageing_score, batch_bonus — but never says how they combine into a single
   number. Is it pdd_score + ageing_score + batch_bonus? A product? Separately weighted? Without the final formula, the
  solver has nothing concrete to optimize on.
  
  IMPORTANT Answer: Yes, Urgency_weight formula is pdd_score + ageing_score + batch_bonus, but there is a catch here., 
  batch_bonus should only be given to orders whose PDD falls in less than 2 months from the Current_date of processing.

  C2 — "No partial batches across shifts" conflicts with large orders.
  CLAUDE.md states each (order, operation) batch is atomic within a shift block — meaning all pieces of one operation for
  one order must land in a single shift. But if an order has (say) 10 pieces × 90 min CT = 900 min, and a shift only has
  ~420 min of available capacity, that batch can never physically fit in one shift. This constraint would make many large
  orders unschedulable. Needs a decision: should large operations be allowed to span multiple shifts, or is there a maximum
   order quantity that makes this safe in practice?
   
   Answer: Partial batches are allowed but only if the qty cannot be completed in that particular available shift, 
   and the partial batch should only be allotted to the next immeadiate shift.

  C3 — Precedence constraints break when non-routed operations exist in the chain.
  The CP-SAT model enforces: start of Op_n+1 ≥ end of Op_n. But if Op_n (e.g., Blasting) has no routing entry and is
  therefore excluded from the CP-SAT model, there is no end_op_n variable to anchor the constraint for Op_n+1. The report
  mentions "Precedence constraints respecting full operation chain (including non-scheduled ops as pass-throughs)" but the
  implementation of this pass-through is undefined. How should the engine determine the estimated completion time of a
  non-scheduled operation in order to set the start constraint for the next scheduled one?
  
  Answer: Do not consider the non scheduled operation while scheduling and while determining the completetion time. 
  Map the previous operation of the pass-through as Op_n for the Op_n+1
